3. ASYNCHANDLER (The Safety Net)
   │
   ├── Runs Promise.resolve() ──► [ Drops down into the Controller ]
   │                                           │
   ▼                                           ▼
4. REGISTERUSER CONTROLLER ────────────────────┴──► Runs your actual code logic:
                                                    ├── Checks inputs & database
                                                    └── Uploads files to Cloudinary
   ▲                                           ┬──► [ Returns the Final Result ]
   │                                           │
   ├── IF SUCCESSFUL: Resolves Promise.        │
   │   Sends clean user JSON data to client.   │
   │                                           │
   └── IF CRASHED: Rejects Promise. ───────────┘
       Hits .catch() ──► Executes next(err) ──► Jumps straight to Global Error Handler

VVVVVVVVVVV. IMP:

1. The Promise is Born: The asyncHandler runs Promise.resolve(), which instantly creates a Pending Promise the absolute millisecond your controller starts.

2. The Code Executes: The entire code inside your registerUser function executes line-by-line (validating inputs, querying MongoDB, uploading to Cloudinary).

3. The Verdict: Once that line-by-line execution hits the very end, the asyncHandler promise finally flips to Resolved (if it finished cleanly) or Rejected (if a line crashed or threw an error).

4. If any line inside your registerUser controller crashes or throws an error (like throw new ApiError), the underlying promise immediately flips to Rejected.This instantly forces the execution to skip the rest of the controller code and jump straight into the .catch((err) => next(err)) block inside your asyncHandler.

5. When next(err) runs inside your asyncHandler, the control goes straight to your Global Error-Handling Middleware located at the bottom of your app.js file.Express instantly halts the regular route chain and searches your code for a middleware function with exactly four parameters: (err, req, res, next).
